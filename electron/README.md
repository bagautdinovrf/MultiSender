# MultiSender Electron

Отдельная версия MultiSender на Electron, TypeScript, React и CSS. Исходная
версия на C++23 / Qt и её пакет `build_agent/package` сохраняются отдельно.
Electron собирается в `build_electron/package/MultiSender Electron.exe`.

## Сборка и запуск

Для сборки нужны Windows x64, Python 3 и Node.js **22.12 или новее**, включая npm.
Qt и компилятор C++ для этой версии не требуются. Первой сборке нужен интернет
для загрузки npm-зависимостей, Electron и инструментов упаковки.

Из корня репозитория:

```powershell
py -3 Installer\build_helper.py --electron --deploy
& '.\build_electron\package\MultiSender Electron.exe'
```

Также можно открыть `electron/Start-MultiSender.cmd`. Для передачи приложения
на другой компьютер копируйте **всю папку** `build_electron/package`.
Устанавливать Node.js на компьютере пользователя не нужно.

Архив для распространения без личных коллекций и истории:

```powershell
py -3 Installer\build_helper.py --electron --deploy --zip
```

Он появится в `build_electron/MultiSender-Electron-<VERSION>-win-x64.zip`.
Пакет собирается из отдельной промежуточной папки и не включает пользовательские
файлы установленной копии.

Полная пересборка с сохранением настроек:

```powershell
py -3 Installer\build_helper.py --electron --clean --deploy --install
```

`--clean` очищает только `build_electron`. Настройки, коллекции и история
Electron, а также файлы `MultiSender.*`, `MultiSenderQml.*` и `HttpRequester.*`,
если они лежат в этой папке пакета, предварительно копируются во временную
папку вне `build_electron` и восстанавливаются после успешной сборки.
При ошибке резервная копия остаётся на диске; её расположение выводится в журнал.
Обычный `--deploy` обновляет файлы приложения без очистки пользовательских данных.

Для выбора отдельного Node.js используйте `--node 'C:\путь\node.exe'` или
переменную окружения `NODE_EXE`. Флаг `--install` выполняет `npm ci`, если есть
lockfile. Без него зависимости устанавливаются только при отсутствии `node_modules`.

Для работы над интерфейсом:

```powershell
cd electron
npm install
npm run dev
```

`npm run dev` собирает приложение и открывает окно Electron. После правок его
нужно перезапустить. Официальный пакет всегда собирается через
`Installer/build_helper.py`; прямой `npm run package` создаёт только промежуточный
пакет в `build_electron/staging`.

## Пользовательские данные

Electron использует собственные файлы рядом с упакованным приложением:

| Данные | Файл |
| --- | --- |
| Настройки интерфейса | `MultiSenderElectron.settings.json` |
| Коллекции и запросы | `MultiSenderElectron.workspace.json` |
| История | `MultiSenderElectron.history.json` |

В режиме разработки данные находятся в `electron/data`. Копию для обычного
использования размещайте в папке с правом записи, например в своей папке
приложений. Исходные файлы Qt-версии не перезаписываются.

Номер версии берётся исключительно из корневого `VERSION`. Упакованное приложение
включает этот файл и `CHANGELOG.md`, а номер в свойствах EXE задаётся при сборке.

## Интерфейс и работа

- Тёмная и светлая темы, изменяемая ширина дерева и высота редактора и подробностей.
- Коллекции и запросы во вкладках; создание, переименование, копирование,
  удаление и изменение порядка перетаскиванием.
- HTTP GET/POST с пользовательскими заголовками, TCP, UDP и COM.
- Адрес, порт, интервал и параллельность наследуются от коллекции;
  каждый параметр можно переопределить отдельно.
- Одиночная отправка и периодический цикл, остановка с отменой активных операций.
  Закрытие вкладки не останавливает запросы. Изменения параметров циклического
  запроса применяются после остановки и повторного запуска.
- Общий и отдельные журналы с поиском, фильтрами, JSON, исходным текстом,
  HEX и заголовками. Хранятся последние 1000 записей каждого запроса.
- Импорт JSON заменяет текущее рабочее пространство после подтверждения;
  экспорт сохраняет коллекции отдельно. История при импорте остаётся на диске.

`Ctrl+Enter` — отправить один раз; `F5` — запустить/остановить; `Ctrl+L` —
перейти к пути или данным; `Ctrl+S` — сохранить. Остальные изменения
сохраняются автоматически; закрытие окна ожидает завершения сохранения.

В TCP/UDP/COM поддерживаются обычный UTF-8, байты `\xHH` и буквальный
обратный слеш `\\`. Разделители не добавляются. Ответ TCP собирается до
закрытия соединения или таймаута, UDP — до первой датаграммы от адресата,
COM — в течение заданного таймаута. Без ожидания успех означает передачу
данных локальному стеку или драйверу, а не подтверждение удалённого устройства.

Для HTTP сохранён таймаут неактивности 30 секунд. Начальный адрес — HTTP;
поддерживаются перенаправления, включая HTTPS, с обычной проверкой сертификата.
Размер исходящего сообщения и полученного ответа ограничен 16 МиБ,
UDP — 65 507 байт. Для больших ответов интерфейс сокращает видимую часть
текста, сохраняя полное содержимое в журнале и при копировании.

COM проверен на перечисление и корректную обработку отсутствующего порта.
Обмен с физическим устройством необходимо проверить с нужным оборудованием.
